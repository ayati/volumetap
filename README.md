# volumetap

ボリュームボタンの短押しで、画面を 1 画面ずつスクロールする Android アプリ。
設定した位置をタップすることもできます。長押しは本来の音量調整のまま。

広告なし・課金なし・オープンソース。`INTERNET` 権限を持たないため、
情報が外部に送信されることは技術的にありません。

ブラウザで読む Web ページ、X のタイムライン、Google Discover、RSS リーダーなど、
指でスクロールして読むアプリを、物理ボタンでページ送りするためのツールです。
ePub リーダー [yomikake](https://github.com/ayati/yomikake) のような、画面タップで
ページを送るアプリにも使えます。

> ⚠️ **ベータ版**です（v0.11.0）。テスターを募集しています。

## 使い方

1. アプリを起動し、「設定を開く」から端末のユーザー補助設定で volumetap を有効にする
2. 「アプリを追加」から、ページ送りに使うアプリ（Chrome、X など）を選ぶ
3. 追加したアプリでは、**音量−で次の画面へ送り、音量＋で前の画面へ戻ります**

キーごとの動作は、アプリごとに次の 4 つから選べます。

| 動作 | 内容 |
|---|---|
| 本来の音量調整 | 横取りしない |
| ドラッグで次の画面へ送る | 画面の中央を下から上へなぞり、1 画面ぶんスクロールする |
| ドラッグで前の画面へ戻す | 画面の中央を上から下へなぞり、1 画面ぶん戻る |
| 指定位置をタップ | 登録した位置をタップする（タップでページを送る電子書籍アプリ向け） |

**Google Discover** を使う場合は「Google」を選んでください。ホーム画面の左に出る
Discover も Google アプリとして扱われます（「Google ニュース」は別のアプリです）。

ドラッグは指の操作をそのまま再現するので、指でスクロールできる画面ならたいてい動きます。
送る量は画面の高さの 6 割ほどで、前の画面の最後の数行が次の画面の先頭に残ります。

追加していないアプリ（ホーム画面を含む）では「その他のアプリ」の設定が使われます。
初期状態は両キーとも「本来の音量調整」です。**明示的に割り当てるまで、端末の挙動は
一切変わりません。**

タップを使う場合は「登録」から、タップさせたい位置を画面上でタップして登録します。
横持ちでも使いたい場合は、端末を横にした状態でもう一度「登録」してください。
横の座標が未登録なら縦の比率がそのまま流用されます。

### Xiaomi / Redmi / POCO 端末では省電力の設定が必要

HyperOS（MIUI）の省電力機能は、裏で動く volumetap を数秒で凍結します。凍結中は
ボリュームキーが届かず、**アプリを切り替えたあとなどに効かなくなります**。
設定画面に案内が出たら、次の順に設定してください。

1. 「アプリ情報を開く」→「電源」→ バッテリーセーバーを **「制限なし」** にする
2. 端末の設定 →「アプリ」→ 画面上部の **「バックグラウンドでの自動起動」** で
   volumetap をオンにする
3. **ユーザー補助を有効にし直す。** 上の設定を変えると端末がアプリを強制停止し、
   ユーザー補助がオフになります

HyperOS 3.0.304（Redmi Note 15 5G）で確認した画面の名前です。端末や版によって
表記が異なることがあります。

### 一時停止

動画を見るときなど、追加したアプリで音量を普通に使いたいときは
**一時停止**してください。クイック設定タイル（通知パネルの編集から追加）で
ワンタップで切り替えられます。設定画面のスイッチからも操作できます。

### yomikake と組み合わせる

yomikake 側のタップ領域設定を「左右の端」にしたうえで、縦書き・縦持ちなら:

| キー | 登録位置 |
|---|---|
| 音量 − | 画面**左**端の中ほど（縦書きの「次」） |
| 音量 ＋ | 画面**右**端の中ほど（縦書きの「前」） |

画面中央は yomikake の操作メニューなので避けてください。
横書きの本では「次」が右端に切り替わるため、割り当ても左右逆になります。

**yomikake を PWA（ホーム画面に追加）として使っている場合**、「アプリを追加」では
yomikake ではなく **Chrome などのブラウザ**を選んでください。PWA はブラウザ上で動くため、
アプリ一覧に独立して現れません。このため、Chrome の割り当てを「タップ」にすると
一般の Web サイトでもタップになり、「ドラッグ」にすると yomikake でもドラッグになります。
読み分けたい場合は、使わないほうの場面でクイック設定タイルから一時停止してください。

## 制約

| 制約 | 内容 |
|---|---|
| セキュア画面 | `FLAG_SECURE` の画面（銀行アプリなど）にはタップを注入できません |
| システム UI | 通知シェード、クイック設定などの上には注入できません |
| 画面消灯時 | 消灯中のキーイベントは端末依存で不安定です。サポート対象外 |
| メーカー独自 | 一部端末は電源管理でユーザー補助サービスを停止することがあります。Xiaomi 端末の対処は「使い方」を参照 |
| 引っ張って更新 | 一覧の先頭付近で「戻す」と、アプリによっては更新が走ります。Google Discover は先頭から 1 画面以内で戻すと一覧が入れ替わり、直前の記事に戻れなくなります。Discover では音量＋を「本来の音量調整」のままにするのがおすすめです |
| 下から出る画面 | 共有シートなど、下から出る画面の上で「戻す」と、その画面が閉じることがあります |

## プライバシー

- **画面の内容を読み取りません。** `canRetrieveWindowContent` を宣言していないため、
  表示されている内容を取得する能力そのものを持ちません
- **ネットワークに接続しません。** `INTERNET` 権限を要求していません
- 前面アプリのパッケージ名のみ、誤爆防止のために参照します
- インストール済みアプリの一覧は、`QUERY_ALL_PACKAGES` ではなく `<queries>` 宣言で
  ランチャーに出るアプリだけに絞って取得しています

プライバシーポリシー: https://www.ayati.com/privacy.html

## ビルド

```bash
./gradlew :app:testDebugUnitTest   # 単体テスト
./gradlew :app:assembleDebug       # デバッグ APK
./gradlew installDebug             # 実機へインストール
```

必要なもの: JDK 17 以上、Android SDK（platform 36 / build-tools 36.0.0）。

`keystore.properties` が無い環境でもビルドは通ります（リリースは未署名 APK になります）。

### リリース

```bash
./make_release_key.sh              # 初回のみ。署名鍵を作成する
./gradlew :app:assembleRelease     # 署名済み APK
./verify_release.sh                # リリース前チェック

./gradlew :app:bundleRelease       # Play 用の AAB
./verify_bundle.sh                 # AAB の検証（bundletool が必要）
```

⚠️ 署名鍵は一度作ったら変更できません。変えると配布済み APK からの上書き更新が
できなくなります。`volumetap-release.jks` と `keystore.properties` は
必ず別の場所にバックアップしてください。

### APK の検証

配布された APK が正規のものかは、署名証明書の指紋で確認できます。

```bash
apksigner verify --print-certs volumetap-0.9.0.apk | grep "SHA-256 digest"
```

期待値（`release-fingerprint.txt` と同じ）:

```
f3d9d749857baa6b402f09c475a6c679fcb861bb2bb447430aae4c340bf37d40
```
